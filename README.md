# Esports Pulse

Русскоязычный сайт с новостями киберспорта, прямыми трансляциями, расписанием, турнирами и карточками игроков. Статический интерфейс получает данные через Cloudflare Worker. Сборка и установка npm-зависимостей для локального запуска сайта не нужны.

## Локальный запуск

Нужен Node.js 22 или новее.

```sh
npm start
```

Откройте `http://127.0.0.1:4173`. Сервер слушает только локальный интерфейс и отдаёт только публичные файлы. Адрес API задан константой `API` в `app.js`. Если Worker ограничивает CORS, добавьте `http://127.0.0.1:4173` в его `ALLOWED_ORIGIN` вместе с рабочим доменом через запятую.

```sh
npm run check
npm test
```

Проверки используют встроенный инструментарий Node.js. Юнит-тесты подменяют внешние ответы и не требуют токенов PandaScore. Они не заменяют проверку браузера и доступности настоящего API.

## Файлы

- `index.html` — структура страницы, заголовки и метаданные.
- `styles.css` — адаптивное оформление, светлая и тёмная темы.
- `app.js` — загрузка данных, навигация и взаимодействие с интерфейсом.
- `app-core.js` — общие функции данных и фильтрации.
- `worker.js` — PandaScore, Liquipedia, RSS, перевод новостей и существующая интеграция Telegram.
- `sw.js` — офлайн-кэш оболочки сайта.
- `scripts/serve.mjs` — локальный сервер без зависимостей.
- `tests/` — автоматические проверки.
- `vercel.json` — маршруты карточек и заголовки статического хостинга.
- `wrangler.toml` — конфигурация Cloudflare Worker.

Выбранная игра, тема, сохранённые новости и избранное хранятся в браузере. Между устройствами они не синхронизируются. Новости автоматически читаются из RSS; список источников находится в `FEEDS` в `worker.js`.

## API и данные

Worker скрывает токен PandaScore от посетителей. Для расписания поддерживаются `game`, `page`, `from` и `to`: фильтр применяется до пагинации. Время начала отображается в часовом поясе устройства. При недоступности внешних источников возможны пропуски данных — пустое расписание не следует считать подтверждением отсутствия событий.

Лимиты запросов и доступность подробной статистики зависят от текущего тарифа PandaScore. Проверяйте их в кабинете поставщика; кэш уменьшает нагрузку, но не отменяет лимиты. Для Liquipedia настройте настоящий контактный `LP_USER_AGENT` и соблюдайте правила API и атрибуции источника. RSS-источники могут менять формат и ограничивать доступ.

Service worker сохраняет оболочку сайта, а не внешние ответы API. Без интернета можно открыть интерфейс и сохранённые в браузере данные; актуальные матчи и новости требуют подключения. Старые кэши Esports Pulse очищаются при активации новой версии; runtime-кэш ограничен 60 записями.

## Развёртывание API в Cloudflare

Публикация выполняется отдельно от сайта. Следующие команды запускаются вручную из корня проекта после входа в свой аккаунт Cloudflare:

```sh
npx wrangler login
npx wrangler secret put PANDASCORE_TOKEN
npx wrangler secret put ALLOWED_ORIGIN
npx wrangler secret put LP_USER_AGENT
npx wrangler deploy
```

Секреты вводятся в интерактивный запрос Wrangler, а не в код. `ALLOWED_ORIGIN` — адрес сайта без завершающего слэша; для нескольких адресов используйте запятую. Укажите выданный адрес Worker в `API` в `app.js`.

Перед первым деплоем в **новый** Cloudflare-аккаунт создайте своё KV-хранилище командой `npx wrangler kv namespace create KV` и замените `kv_namespaces.id` в `wrangler.toml`. При обновлении существующего проекта сохраняйте его текущий binding. Конфигурация также использует Workers AI для перевода; проверьте доступность этой услуги в своём аккаунте. Telegram и его расписание уже присутствуют в Worker; включение бота, настройка webhook и отправка сообщений не выполняются командами локальной проверки.

## Публикация сайта в Vercel

Публикуйте статический сайт отдельно от API. Чтобы не отправлять весь рабочий каталог, подготовьте отдельную папку с публичными файлами. Пример для PowerShell из корня проекта:

```powershell
New-Item -ItemType Directory -Force -Path .\public
Copy-Item -LiteralPath index.html,styles.css,app.js,app-core.js,sw.js,manifest.webmanifest,icon.svg,icon-192.png,icon-512.png,og.png,vercel.json -Destination .\public
Set-Location .\public
npx vercel
```

При настройке этого статического проекта выберите preset **Other**, без команды сборки, с текущей папкой в качестве output directory. Команда `npx vercel` создаёт preview-развёртывание; для выпуска проверенного сайта в production используйте `npx vercel --prod`. При повторной публикации сначала обновите копии файлов из корня проекта. Не копируйте в папку публикации секреты, `.dev.vars`, `.env` и локальные каталоги инструментов. API развёртывается отдельно в Cloudflare.

`vercel.json` перенаправляет `/player/…`, `/team/…` и `/tournament/…` на оболочку приложения. На другом статическом хостинге нужны аналогичные rewrites, иначе прямые ссылки на карточки вернут 404. После публикации проверьте прямую ссылку на карточку, загрузку API и обе темы.

## Домен и превью ссылок

В `index.html` уже указан локальный путь `/og.png`. После выбора рабочего домена замените его в `og:image` на полный HTTPS-адрес картинки и добавьте `og:url` и `link rel="canonical"` с реальным адресом сайта. Не используйте выдуманный домен: проверьте, что картинка доступна без входа в аккаунт. Для страниц игроков и команд отдельные превью потребуют серверной генерации метаданных; изменение заголовка в браузере само по себе этого не обеспечивает.
